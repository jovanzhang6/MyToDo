# 限时任务升级：天 → 天+时:分，到期前 1 小时 / 15 分钟双段提醒

## 一、UI 设计（核心：不增加一行高度，不动小窗骨架）

### 添加条（选中「限时」时，内容宽 258px 的预算内）

```
现在：  [不限时] [每日] [限时]
        截止 [2026/10/05📅] [+1天]
        [要做点什么？回车添加      ] [✓]

改为：  [不限时] [每日] [限时]
        [2026/10/06📅] [18:30🕐] [+1时] [+1天]
        [要做点什么？回车添加      ] [✓]
```

- **行数不变**（仍是 3 行）：pills 行 156px，日期组换行独占第二行——现状也是如此（flex-wrap 已存在）。
- **去掉「截止」二字标签**（省 30px）：原生 date/time 输入自带日历/时钟图标，语境自明；这是能同时放下时间输入和两个快捷键的唯一解。
- 宽度核算：date 压到 94px + time 62px + [+1时]38 + [+1天]38 + 3×gap4 ≈ **248px ≤ 258px** ✓（现 date 104px 略压缩，字号 11px 不变，圆角胶囊样式完全沿用）。
- `+1时` = 整个到期时刻 +1 小时（可滚过午夜）；`+1天` = 日期 +1、时刻不动。均为既有 `.quick` 胶囊样式。
- **默认时刻 23:59**：选「限时」未动时间 = 当天最晚，与旧的天粒度语义完全一致，零意外。
- **过去时刻校验**：添加时若到期时刻 ≤ 现在，后端拒绝，tip 提示「这个时间已经过了，选一个未来的时刻」。

### 任务行徽章（文案阶梯，最多 96px，红/琥珀配色体系不变）

| 距到期 | 徽章 | 样式 |
|---|---|---|
| ≥2 天 | 限时 · 后天到期 / N天后到期 | 琥珀（**与现在完全一致，零变化**） |
| 明天 | 限时 · 明天 18:30 | 琥珀 |
| 今天 | 限时 · 今天 18:30 | 红（沿用现有 `.due-today`） |
| **<15 分钟** | 同上 | 红 + **极轻呼吸脉动**（背景透明度 0.16→0.28，2.4s 循环，无缩放无跳动） |

不引入「1 小时内」第三种颜色状态——状态越少越精致，紧迫感交给那一次脉动。徽章点击的类型/改期气泡（openKindPop）同步加时间输入。旧数据无时刻的限时任务维持「今天到期」文案与旧到期语义（见下）。

### 设置页

「到期提醒」副标题「限时任务到期当天通知一次」→「到期前 1 小时和 15 分钟各提醒一次」。

## 二、提醒设计（Rust 侧计时，前端不参与决策）

- **三个旧约定替换为一个新约定**：废弃「到期当天一条」的日级通知（否则单任务最多被轰 3 次），只发 **T-60min、T-15min** 两段；到期瞬间静默归档（列表消失），不发第三条。
- **只提醒未完成的限时任务**；`reminders_enabled` 总开关照旧生效。
- **去重**：Task 新增 `notified_stage: u8`（0/1/2 = 未提醒/已发1h/已发15m），随任务存进 data.json，重启不重发，任务归档自动清理。
- **触发**：Rust 起一个 30 秒轮询线程（lib.rs setup 挂载，锁 AppState 跑纯函数判定→发 toast→落盘→emit state-changed）；`get_state` 路径保留同一判定做**补发**（休眠唤醒/重启后 30s 内追上），双路径靠 stage 标记天然幂等。
- **休眠补偿**：一觉睡过两个时点 → 只发更紧迫的那一段（stage 取 max），绝不连轰。
- **聚合**：同一轮询窗口内同 stage 的多任务合并一条 toast（沿用现有聚合文案风格）：「1 小时后有 2 件任务到期：课程论文、背20个单词」。
- 判定全为纯函数（`now` 注入），延续 todo.rs「禁止获取系统时间」纪律。

## 三、引擎与数据（serde default 兼容，无需迁移函数）

- `Task` + `#[serde(default)] due_time: Option<NaiveTime>`；`None` = 旧天粒度任务，**按 23:59 到期**（语义 = 当天最晚，旧任务行为几乎不变）。SCHEMA_VERSION 1→2（serde default 双向兼容，不写迁移代码——与项目现有兼容模式一致）。
- 新增纯函数 `due_datetime(task)`（None→23:59）与 `expire_now(db, now)`：时刻级过期归档，挂在 get_state 与轮询线程（roll_over 的逐日重放保持天粒度不动，b9 等价性测试不受影响）。
- 排序：due_date 之后追加 due_time 决胜（None 视作 23:59）。
- `add_task`/`set_kind` 命令加 `due_time: Option<String>`（%H:%M 解析），非限时强制清空；`TaskView` 透出 `due_time`。

## 四、测试（照现有 b/d 编号风格，预计 +10 个左右）

- todo：时刻级过期（到期时刻前存活/后归档）、None→23:59、同日不同时刻排序、过去时刻添加被拒、set_kind 保留/清空 due_time。
- notify：T-60 触发、同 stage 不重发、T-15 依次触发、跳段只发最紧迫、已完成不发、开关关闭不发。
- store：含 due_time 的 roundtrip + 旧 JSON 无该字段解析为 None。
