## 项目目标

一个常驻 Windows 桌面右上角的磨砂玻璃质感 TODO 小组件：用户零维护成本地跟踪「每日任务、限时任务、不限时任务」三类待办——每日任务自动刷新、限时任务按天过期归档、完成情况自动统计、到期自动提醒。

**成功判据**：用户添加「每天刷 20 道算法题」后，从此每天它自己出现；勾掉即划线、次日自动重置；统计面板能看到完成率和连续打卡天数；限时任务到期当天有 toast 提醒、未完成也会在次日归档消失。

## 已确认的产品决定（澄清轮次留痕，2026-09-24）

| 决定点 | 结论 |
|---|---|
| 窗口置顶 | 默认置顶 + 一键切换置顶/普通 |
| 限时任务到期粒度 | 按天（过期日全天有效，次日刷新时消失） |
| 过期任务数据 | 归档保留（标记「过期未完成」），列表中消失 |
| 到期提醒 | Windows 原生 toast（应用常驻时触发）+ 列表内「今天到期」红色高亮 |
| 统计深度 | 全量四件套：按类型完成率 / 近 30 天趋势 / 连续打卡 streak / 过期率；具体设计授权 PM/研发 |
| 生命周期 | 托盘常驻（点 X = 隐藏到托盘）+ 开机自启可在设置中开关 |
| 技术栈 | **Tauri 2（Rust 后端 + Web 前端）**——用户点名：本机可装 Rust，且要求未来跨端到 macOS |
| git | 在 D:\MyToDo init 仓库，按关卡分阶段提交 |

## 全局约定

- **技术栈**：Tauri 2 + Rust（业务引擎）+ TypeScript + Vite 原生前端。**不引入 React/Vue 等框架、不引入组件库与图表库**（图标内联 SVG、趋势图手绘 SVG），守住「轻量」。macOS 适配是后续版本目标，本版只交付 Windows，但代码不得写死 Windows（平台差异收敛到 shell 层）。
- **业务逻辑下沉 Rust**：任务生命周期（跨天重置/过期归档/类型转换/统计计算）全部在 Rust 侧实现并被单元测试钉住；前端只做展示与交互。理由：可单测、跨天等边界不依赖 JS 运行时。
- **数据**：单 JSON 文件（`%APPDATA%/…/data.json`，含 schema 版本号），原子写入（临时文件 + rename）。绝不物理删除任务记录，只做状态归档。
- **「一天」的定义**：本地时区自然日（00:00:00 切换）。应用常驻，午夜定时器触发刷新；休眠唤醒/打开窗口时做补偿计算（按当前日期重放状态）。
- **磨砂实现**：Windows 用 Acrylic，失焦自动回退 Mica/半透明（规避系统级性能怪癖）；纯半透明为最终兜底。
- **共享件归属**：JSON 存储基座、窗口状态持久化、任务与归档 schema → 均归 mytodo-core（第一个需要它们的切片）；mytodo-stats-notify 只读归档数据，不改 schema。
- **工具链安装**：Rust 工具链（rustup + MSVC C++ 生成工具）在 mytodo-core 开工时与业主一起现场安装（业主明确要求共同操作，不代办）。
- **通知/自启/单实例**：官方插件 tauri-plugin-notification / autostart / single-instance，不自造轮子。

## 非目标（v1 明确不做）

1. **macOS/Linux/iOS/Android 适配**——v1 只交付 Windows；架构不排除但不在本版验收。
2. **多设备同步 / 云备份**——单机单文件，无账号体系。
3. **子任务、标签、优先级、自然语言输入**——任务模型保持「一句话 + 类型 + 到期日」的最小形态。

## 开放问题

- 磨砂的默认透明度数值：开发中视觉调优后定（用户要求「非常浅的淡蓝 + 一定透明度」）。
- toast 文案与是否显示任务名：研发阶段定稿。
- macOS 版排期：用户提出未来诉求，未定时间，v1 非目标。
